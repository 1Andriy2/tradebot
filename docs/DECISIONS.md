# Decisions

One line per decision. Newest at the bottom.

- 2026-11-01 — Demo venue: Bybit Demo Trading (`api-demo.bybit.com`), USDT linear perpetuals, long and short.
- 2026-11-01 — Hosting: no Oracle; GitHub Actions cron (one-shot step every 15 min, public repo) + Kaggle for GPU training + Vercel Hobby for the dashboard.
- 2026-11-01 — Hard risk caps (code constants, never learned): position ≤ 25% of equity, leverage ≤ 2x, daily loss ≤ 5%, kill switch at 20% drawdown from peak.
- 2026-11-01 — Learnable risk params (position fraction, leverage, ATR stop/take multiples, entry threshold) are tuned in walk-forward and clipped to the hard caps.
- 2026-11-01 — Env loading via `scripts/with-env.sh` instead of direnv (no global shell hook).
- 2026-11-01 — Project MCP: Supabase (read-only, project-scoped) + GitHub (read-only) in `.mcp.json`; no Vercel MCP (OAuth-only, can make purchases) — Vercel CLI with `VERCEL_TOKEN` instead.
- 2026-11-01 — Python 3.11 managed by `uv` in a project `.venv`; single `pyproject.toml` at repo root.
- 2026-11-01 — The project does not call the Claude API (paid); if ever needed it must use andrijkostelnij72@gmail.com.
- 2026-11-01 — Own bar-by-bar backtest engine instead of vectorbt/backtesting.py: futures long/short, leverage, intrabar stops and the same RiskManager as live trading.
- 2026-11-01 — Strategies emit a target exposure in [-1, 1] per bar from data up to that bar's close; orders fill at the next bar's open plus slippage (no look-ahead).
- 2026-11-01 — Costs in every test: 0.1% fee per side + 0.05% slippage per side; funding payments are not modelled (documented limitation).
- 2026-11-01 — Endpoint allowlist is a code constant; every authenticated HTTP request is host-checked and a non-demo host raises immediately.
- 2026-11-01 — Historical candles come from Bybit's public market-data API via a separate client that never holds keys.
- 2026-11-01 — Local candle cache: Parquet files in `data/` (gitignored), incremental updates.
- 2026-11-01 — Primary ranking metric for champion/challenger: Sortino ratio on out-of-sample folds, with a minimum trade count.
- 2026-11-01 — Backtester and live shadow agents share one bar step (`simulate.step_bar`) and one `DecisionPolicy`, so live rules equal tested rules.
- 2026-11-01 — Every agent runs as a shadow paper book on live candles; only the champion also trades the Bybit demo account.
- 2026-11-01 — Demo sizing uses account equity / number of symbols; stop-loss and take-profit are attached to the entry order on the exchange.
- 2026-11-01 — Steps are idempotent per closed bar (`agent_state.last_bar`), so duplicate cron runs never double-trade.
- 2026-11-01 — Default champion until the first ML model is promoted: `ma_cross`.
- 2026-11-01 — Bot writes with the Supabase service-role key (server only); dashboard reads with anon key + Auth, SELECT-only RLS for `authenticated`.
- 2026-11-01 — Free-tier storage: candles kept 60 days, `hold` decisions 90 days (`prune_old_rows()`).
- 2026-11-01 — Dashboard: Next.js 16 (App Router, `src/proxy.ts` auth gate), client-side reads via `@supabase/ssr` browser client + Realtime; times shown in Europe/Kyiv.
- 2026-11-01 — ML: one pooled LightGBM (BTC+ETH) predicting the 8h (32-bar) direction; 1h features resampled from 15m so training and live use identical code.
- 2026-11-01 — Walk-forward: 24-month rolling train, 3-month test folds, purge = label horizon; last 9 months are an untouched holdout.
- 2026-11-01 — Optuna (30 trials) tunes signal threshold/smoothing and risk params on the pre-holdout OOS period only.
- 2026-11-01 — Promotion: challenger holdout Sortino > champion + 0.05, ≥ 30 trades, holdout max drawdown < 20%; one champion at a time across all agents.
- 2026-11-01 — Live LightGBM model is refit on the latest 24 months after evaluation; LightGBM champions are re-scored via walk-forward (never by replaying a model on data it saw).
- 2026-11-01 — Model files are JSON (LightGBM text model + config + risk params) in a private Supabase Storage bucket `models`.
- 2026-11-01 — RL: PPO (Stable-Baselines3, MLP) with discrete short/flat/long actions; reward = log equity growth after fees/slippage − 2 × new drawdown; trained only on pre-holdout data.
- 2026-11-01 — RL agent: fixed exposure 25% × 1x, no ATR stops (it manages exits); hard caps and kill switch still apply.
- 2026-11-01 — Shared `registry` module handles versions, champion/challenger and model storage for both LightGBM and RL.
- 2026-11-01 — Candle cache mirrored to Supabase Storage (`data` bucket, `--sync`) so CI/Kaggle training works even if the exchange API is unreachable there.
- 2026-11-01 — Kaggle notebook installs the package from the public repo and calls `tradebot rl-train --sync --no-download` (secrets via Kaggle Secrets).
- 2026-11-04 — Kaggle notebook clones the repo and runs `uv sync --frozen` on Python 3.11: Kaggle's Python 3.13 fails `requires-python`. The lock pins CPU torch on Linux, so Kaggle runs on CPU.
- 2026-11-01 — macOS dev only: `OMP_NUM_THREADS=1` (torch + LightGBM OpenMP clash); Linux runs multi-threaded.
- 2026-11-01 — Workflows: CI (ruff, mypy, pytest, dashboard lint/build), trade step at minute 1/16/31/46, nightly retrain 02:17 UTC + prune, weekly CPU RL, monthly keepalive commit, manual venue reachability check.
- 2026-11-01 — Workflow inputs are passed via env (no `${{ }}` interpolation in shell) to avoid script injection.
- 2026-11-01 — CPU-only PyTorch on Linux via a uv index, so the 15-minute job stays light.
- 2026-11-01 — Server mode: one Docker image (python:3.11-slim, arm64/amd64), compose services `trader` (daemon) and `trainer` (nightly loop).
- 2026-11-01 — Known risk: Bybit's CDN may block US cloud IPs (GitHub runners); verify with `venue-check.yml`. No proxy/geo-block circumvention will be used.
- 2026-11-01 — Verified from a GitHub runner: Bybit (demo and public API) returns HTTP 403; Kraken Futures demo is discontinued (redirects to marketing page); OKX and Bitget respond 200.
- 2026-11-01 — Venue for GitHub cron mode: OKX Demo Trading (`EXCHANGE_ID=okx`). Bybit Demo stays supported for local/server mode.
- 2026-11-01 — OKX demo shares the production host, so the guard allowlists host + mandatory `x-simulated-trading: 1` header, checked on every request; demo keys are also rejected by live OKX.
- 2026-11-01 — Orders are sized in base units and converted to contracts via `contractSize` (OKX BTC swap = 0.01 BTC); one-way (net) position mode, cross margin.
- 2026-11-01 — History before November 2026 comes from the Bybit cache; GitHub jobs append newer candles from OKX's public API.
- 2026-11-01 — Live step isolates failures per agent and symbol; a demo-venue error is logged but never stops shadow agents.
- 2026-11-01 — OKX sizing uses USDT equity only (single-currency margin), not the value of all demo coins.
- 2026-11-01 — Hard position cap is enforced every bar: positions above 120% of the cap (25% × 2x of equity) are trimmed back with reason `risk_cap`, in backtests and live.
- 2026-11-01 — Kill switch is never reset automatically; `tradebot reset-kill-switch` exists for an explicit human decision and logs an event.
- 2026-11-01 — Goal shift (user): discover profitable strategies and repeating patterns; fees/slippage/funding are always counted in statistics, but strategies are not tuned to trade less just to save fees.
- 2026-11-01 — Funding rates (Bybit history, OKX updates) are charged in all backtests on positions held through a funding time and recorded per trade (`trades.funding`).
- 2026-11-01 — Strategy library: 12 families (buy & hold, MA cross, RSI, Bollinger, grid, Donchian, MACD, Keltner, time-series momentum, z-score reversion, ADX trend, hour-of-day seasonality) with parameter grids.
- 2026-11-01 — Research = walk-forward parameter selection per family/symbol/timeframe (12-month train, 3-month test, 15m/1h/4h), OOS folds stitched into one backtest.
- 2026-11-01 — Repeatability metrics: share of profitable test folds, per-fold returns, and Deflated Sharpe Ratio over all configurations tried in a run.
- 2026-11-01 — Pattern scan: hour-of-day and day-of-week return effects with Benjamini-Hochberg q-values; "stable" = same sign and p < 0.05 in both halves of history.
- 2026-11-01 — Tests: hypothesis property tests (equity = initial + trade PnL; exposure bounded by caps) and a golden regression file for every strategy family.
- 2026-11-01 — GitHub `schedule` never fired in this repo (hours after enabling and re-registering). Workflows are now triggered by Supabase Cron (pg_cron + pg_net) calling workflow_dispatch; GitHub schedules and the keepalive workflow were removed.
- 2026-11-01 — User-approved exception to "secrets only in .env / GitHub Secrets": a fine-grained GitHub token limited to Actions (read/write) on this repository lives in Supabase Vault (`github_dispatch_token`), added by the owner via the Dashboard; `dispatch_workflow()` is not executable by anon/authenticated.
- 2026-11-04 — A new champion adopts positions it finds on the exchange at the current close (`PaperBook.adopt`), so it can close them and record the trade; the old champion's attached stops stay active.
- 2026-11-04 — External repos are reviewed statically before reuse, and their code is never run next to secrets. Algorithms are reimplemented with credit in the module docstring; no QuantStats or skfolio dependency, because they pull in yfinance, matplotlib, cvxpy and plotly for a few formulas.
- 2026-11-04 — Research robustness (`research/robustness.py`): Ulcer, CVaR, tail ratio, PSR, stationary-bootstrap Monte Carlo, rule significance on detrended returns with BH q-values, CPCV paths, PBO per family and across all configurations of a symbol/timeframe, parameter sensitivity (±20%, ±50%), peers on the other pair and timeframes.
- 2026-11-04 — `robust` = profitable, all available checks passed, at least four checks available. Thresholds are rules of thumb. These numbers are informational and never change which agent trades.
- 2026-11-04 — Three new rule-based families and shadow agents: `regime_switch`, `vol_scaled_trend`, `chandelier_trend` (ideas from agiprolabs/claude-trading-skills, code written here). Grids were fixed from the source's usual values before seeing any result.
- 2026-11-04 — Rule-based agents stay shadow-only: promotion exists only for `lgbm` and `rl`. Adding a path to the demo account would change trading behaviour and needs its own decision.
- 2026-11-04 — `chandelier_trend_4h`: shadow agent that runs on completed 4h candles inside the 15m step (`OnTimeframe`). It matches a native 4h backtest on real data.
- 2026-11-04 — Strategies may set `history_bars`; the step fetches that longer history only for them, once per symbol, without writing candles. 1000 bars of 15m are 63 four-hour candles, too few to warm up; 6400 bars matched full history at every sampled point. Other agents keep the usual window, and a failed long fetch stops only the agent that needs it.
- 2026-11-04 — Historical analogs: `analog` research family and nightly scenario table (events of type `scenario`). A past moment counts only if its outcome was known at the bar being judged. No shadow agent: it needs fitted data live, and the first run showed no predictive power (all 6 results lost money, q ≥ 0.43).
- 2026-11-04 — Market data collection: hourly open interest and long/short ratio (ccxt) and real liquidation orders (OKX public `liquidation-orders`), stored as Parquet in the existing `data` bucket, so no migration and no change to the trade step. Runs inside the nightly jobs; a failure never stops them.
- 2026-11-04 — Exchanges keep little history of these: one run reached about 21 hours of liquidations, so daily runs may leave gaps. Check continuity after a few nights.
- 2026-11-04 — Event studies test the liquidation idea before any strategy uses it: forward returns after spikes against the base rate, overlapping events counted once, q-values per run, nothing tested below 30 events.
- 2026-11-04 — News: headlines from 5 public RSS feeds, stored as `news.parquet` in the `data` bucket. Feed text is untrusted and only stored and counted. Tone is a word count fixed in advance: free and testable, but it does not understand meaning.
- 2026-11-04 — No news or liquidation strategy yet: there is no history to test one on. Event studies run nightly, and a strategy is worth building only if one shows q < 0.05 with enough events. Feeds hold about a day of items, so daily runs may miss some.
- 2026-11-05 — News risk filter, stage 1: `tradebot news` collects, scores and writes a risk level, and trading does not read it. A shadow agent is the next stage; a demo-account gate needs its own decision and the existing q < 0.05 test.
- 2026-11-05 — Own code with no new dependencies. No reviewed repo was installed: `congressional-trades` caches random fake trades when scraping fails and its source repo is gone; `cryptocurrency.cv` is proprietary despite "free"; kansoku (formerly innei/trade-skills) is Commons Clause; worldmonitor is AGPL, so only ideas and public URLs were reused.
- 2026-11-05 — Free LLMs called with httpx: Gemini (`gemini-3.5-flash-lite`), then Groq (`openai/gpt-oss-120b`). Only public news is sent. GitHub Models was retired on 2026-07-30.
- 2026-11-05 — Reddit is not a source: its RSS ends 2026-11-13, new API requests closed on 2026-10-31, and the rest closes by March 2027. Truth Social comes from the independent trumpstruth.org feed, because the official feed is paid.
- 2026-11-05 — GDELT comes from the raw 15-minute files, because the DOC API returned 429 on the first call. It is limited to 3 new stories a run: at about 20 a run it would use the daily budget in hours.
- 2026-11-05 — The news job gets no exchange keys, and levels can only reduce exposure, so a crafted headline can at worst make the bot trade less. One source can trigger `reduce` but never `stand_aside`.
- 2026-11-05 — News scoring cannot be backtested, because a model may remember what followed old news. Items over a day old are never scored, and tests must use `first_seen`, which also records the prompt version and model.
- 2026-11-05 — News scores live in their own Parquet files outside `sync._paths`, or the nightly sync would overwrite them with an older copy. A failed download stops the run instead of uploading an empty table over the history.
- 2026-11-05 — News filter, stage 2: `news_<champion>` runs a shadow book with the champion's signal scaled by the news level. It has kind `baseline`, so it cannot be promoted, and the demo account is unchanged. Without levels, or with levels over an hour old, it follows the champion.
- 2026-11-05 — The risk formula is known to saturate (about 40 events gave pressure 0.97 on both sides) and stays as it is until there are days of data. Scores are stored, so levels can be recomputed, but the twin's book reflects the formula in force at the time.
- 2026-11-05 — Gemini model is `gemini-3.1-flash-lite`: on a real 20-item batch it answered in 4 to 5 seconds, while `gemini-3.5-flash-lite` and `gemini-3.6-flash` returned 503 and `gemini-2.5-flash-lite` returned 404.
- 2026-11-05 — Nightly research now tests the model's strong ratings (|impact| ≥ 0.5) and the filter's cuts with the existing event study, on `first_seen`, one count per story, current prompt and primary model only, because the fallback model rates the same news differently. A demo-account gate needs q < 0.05 with at least 30 events here.
- 2026-11-05 — A second news twin, `news_ma_cross`: `rl` held a position 3.3% of the time over 4 days, so its twin would show the filter almost nothing. `ma_cross` is always long or short. Both twins stay shadow-only.
- 2026-11-05 — The dashboard's `/news` page reads `news_items` and `news_levels` (SELECT-only RLS). Parquet stays the full record, and a failed table write never stops a news run. Stories are kept 30 days in the table.
- 2026-11-05 — Prompt version 2: the model also returns a Ukrainian headline and a Ukrainian reason, for the page. Feed text is only ever rendered as plain text.
- 2026-11-05 — News files fetched every 15 minutes keep only about 3 to 4 days of rows; older rated rows move daily to `news_scored_YYYY-MM.parquet` and `news_risk_YYYY-MM.parquet`, which only nightly research reads. Supabase's free plan has 5 GB of egress a month, and a file that only grows would pass that in about a month. Rows that were never rated are dropped at rotation.
- 2026-11-05 — Correction: `ma_cross` has a signal all the time but held a position only 28% of the last 4 days, because it waits after a stop. `news_buy_hold` (always long) joins as the steadiest test of cutting longs; `news_ma_cross` covers shorts.
- 2026-11-05 — The news filter passes a position `scale` to `DecisionPolicy.decide` instead of changing the signal: a scaled signal counted as a new signal and ended the wait after a stop, which could open a position. Scale applies to the size the signal last asked for, so a cut and release cannot exceed it. With the default scale of 1 decisions are unchanged.
- 2026-11-05 — A story ages from its first appearance, so a repeat does not refresh it, and only sources with weight ≥ 0.2 count toward the two needed to stand aside. Nightly q-values are computed over all event studies of a run. A rating counts from `scored_at` when that is later, and a filter episode counts once.
- 2026-11-05 — Event studies mark the candle labelled with the event's hour (floor, not ceil): candles are labelled by their open, so that candle is the first to close after the event. This also corrects the word-count `news_studies`.
- 2026-11-05 — Levels go `unknown` when at least 5 items are over an hour behind, not on one: an item the model never answers validly could otherwise switch the filter off, and a crafted headline could do that on purpose.
